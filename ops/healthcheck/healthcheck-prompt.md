# 母艦ヘルスチェック（毎朝実行）

あなたはMac mini母艦の自己点検エージェントです。以下を順に確認し、最後に判定を1回だけ出力してください。
**読み取り専用。修復・設定変更・ファイル書き込みは一切しない。異常を見つけても直さず報告するだけ。**

## 点検項目

1. **MCPサーバー接続状態**
   `claude mcp list` を実行し、接続失敗（`failed` / `not connected` / エラー表示）のサーバー名を列挙する。
   サーバー総数と失敗数を数える。1本でも失敗していれば異常。

2. **freee認証の生存確認**
   `mcp__freee__freee_auth_status` を1回呼び、トークンが有効かを確認する。
   未認証・失効・要再認証なら異常。

3. **Gmail認証の生存確認**
   `mcp__Gmail__search_threads` で軽い読み取りを1回だけ実行する（例: `in:inbox`、取得は1件）。
   認証エラー（invalid_grant / 要再認証）が出たら異常。メールの内容は読まないし要約もしない。

4. **reg-monitorの更新確認**
   `curl -sS --max-time 30 "__REG_MONITOR_DATA_URL__"` の先頭部分から `generatedAt`（ISO8601・UTC）を読む。
   巡回はGitHub Actionsの `crawl.yml` が **毎時37分（1日24回）** 回している。
   したがって `generatedAt` が現在時刻から **__STALE_HOURS__時間** 以上前なら異常（巡回失敗、またはGitHub Pagesへの公開失敗）。
   ファイルは大きいので全体を読み込まないこと（`head -c 200` 等で先頭だけ見る、または `jq -r .generatedAt` に流す）。
   ※これは母艦のローカルcloneではなく**公開中の出力**を見る点検である。ローカルの `git log` は母艦がpullしていなければ古いだけで、パイプラインの健全性を示さない。

5. **母艦リソース**
   `df -h /` でディスク使用率、`uptime` で負荷を確認する。
   ディスク使用率が90%を超えていたら異常。

## 出力ルール（厳守）

最終メッセージは、次のどちらかの形式で**必ず先頭トークンから**始めること（スクリプトが先頭で判定する）。
前置き・挨拶・作業説明は書かない。

- **全項目正常**:
  `OK: MCP <成功数>/<総数>, freee OK, Gmail OK, reg-monitor OK (generatedAt <値>), disk <使用率>%`
  の1行だけを出力する。**Slackには何も送らない。**

- **1つでも異常**:
  1行目を `ALERT: ⚠️ 母艦ヘルスチェック異常 <YYYY-MM-DD>` とし、
  2行目以降に**異常だった項目のみ**を箇条書きで書く（正常だった項目は並べない）。
  各行には「何が」「どういう状態か」「観測値」を入れる。
  同じ内容を Slack MCP で **三根さんへDMで1回だけ**送る。
  `mcp__Slack__slack_search_users` でメールアドレス `kimihiro.mine@finoject.com` から本人を特定し、
  そのDMへ `mcp__Slack__slack_send_message` で送ること。**他のチャンネルへは投稿しない。**
  ただし `__SLACK_CHANNEL__` に値が入っている場合に限り、DMではなくそのチャンネルへ送る。
  Slack送信は1回だけ。失敗しても再送を繰り返さず、その旨を最終メッセージに書く。

- 判定に迷う場合（ツールが呼べない・出力が読めない等）は正常扱いにせず `ALERT:` 側に寄せ、
  「点検自体ができなかった項目」として書く。見逃しより誤報の方が安全。
